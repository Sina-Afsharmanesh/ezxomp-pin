# Changelog

All notable changes to this project are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Every change that lands on `main` must add an entry here — see `AGENTS.md` § Work Guidance.

## [Unreleased]
### Changed
- **extensible-workflows typed tool schemas** (Ollama `api.ToolProperty` 400 fix): `omp_workflow_route.route` is now a real object schema (`mode` enum direct/chain, `steps` array with `workflow`/`inputs`/`resultRef`, optional `maxDepth`) instead of `z.unknown()`, and `omp_workflow_gate.evidence` is a typed record instead of `z.unknown()`. The host wire converter (`pi-ai` `normalizeEmptySchemas`) emits bare JSON `true` for `{}` property schemas, and Ollama Cloud's strict Go backend rejects bool-valued entries in tool `properties` maps with `400: json: cannot unmarshal bool into Go value of type api.ToolProperty` - these two tools made every tools-bearing completion against an Ollama upstream fail through 9router/OmniRoute-style gateways. `additionalProperties` bools are unaffected (Ollama ignores them).
- **better-custom 9router metadata probe**: the Ollama probe now detects a 9router gateway via its `/api/version` marker (`currentVersion` without Ollama's `version` field) and prefers the real OpenAI-style `/v1/models` catalog over 9router's static placeholder `/api/tags` list; a confirmed gateway with an empty OpenAI list returns empty instead of placeholder models. Inline model-list parsing accepts 9router's camelCase `capabilities` blocks (`contextWindow`/`maxOutput`/`thinkingFormat`) and `max_completion_tokens` output limits. `ollama-chat` compat now enables `supportsReasoningEffort` (with the gateway's `thinkingFormat` hint, e.g. `zai`) when probe evidence carries a real thinking format — genuine Ollama endpoints keep effort disabled.
- **gsd-web OMP project-first launch:** `GSD_WEB_PROJECT_CWD` selects the active project before boot; onboarding no longer repeats project selection. Launches without a supplied project retain the project picker, and explicit switching remains in the Projects panel.
- **gsd-web MCP imports:** discovered stdio MCP servers now preserve their typed transport and command when copied into project-local `.gsd/mcp.json`; importing no longer falls into HTTP validation because the executable name was passed as the transport.
- **Git worktree controls:** native-Git isolation now accepts valid `bare` and detached porcelain records, reattaches a preserved `task/<slug>` branch after cleanup, and refuses cleanup before a clean status probe. Selected isolation without a name now fails closed; failed workflow stages journal their failure without waiting on completion evidence.
- **Plannotator 0.25.1-ezxomp.2 / Cook 0.1.7-ezxomp.8:** marketplace versions now ship the native-Git cutover. Plannotator removes Jujutsu review artifacts and CLI permissions while retaining Git/GitButler review; Cook profiles require task Git worktrees and immutable `HEAD` OIDs.
- **Git workflow migration:** replaced Jujutsu-first repository guidance with native Git worktrees and `task/<slug>` branches; workers commit locally and report branch plus immutable commit OID, while coordinator alone integrates into `main`, runs gates, and pushes `origin/main`. Active SPEC, agent profiles, and operational docs now use Git terms; historical changelog/backlog mentions remain unchanged.
- **better-custom 0.1.1-ezxomp.0** (TASK-106): version bump shipping the 9router gateway compatibility fix — Ollama-probe gateway-subpath tolerance, `/api/tags`-failure fallback to the OpenAI-style model list, and the bool-ToolProperty 400 citation on `ollama-chat` compat defaults. Marketplace manifest, README table, and `test/manifest.test.ts` expectations updated in lockstep.
