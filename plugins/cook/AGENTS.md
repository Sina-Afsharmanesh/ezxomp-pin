# AGENTS.md — cook

## Purpose
Backlog.md cookbook workflow plugin for OMP. Decomposes work into atomic sub-tickets and drives scout/planner/worker/judge agents through OMP's native `task` tool, with ADHD divergent ideation, DAG iteration, and Done-gate enforcement.

## Ownership
- Package: `@ezxomp/cook` (fork of `pi-backlog-cook`)
- Entry: `extensions/index.ts` — registers all cook_*/backlog_* tools and `/cook` command

## Local Contracts
- Imports `Type` from `typebox` (not `@oh-my-pi/omptype/typebox`). OMP's marketplace install does not run npm/bun install, so peer packages are not on the plugin's module resolution path; the host ships the original `typebox` in the plugin node_modules.
- Peer dep: `@oh-my-pi/pi-coding-agent` 18.0.6
- Vendored `js-yaml@4.3.1` + `argparse@2.0.1` under `vendor/` (see `vendor/VENDORED.md`); loaded via the in-tree ESM wrapper `vendor/js-yaml.mjs`. OMP marketplace install does not run npm/bun install, so tests import `../vendor/js-yaml.mjs`, never bare `js-yaml` — and never a cross-plugin path into `plugins/evo/` (each cache copy is a separate tree; `../../evo/...` breaks on marketplace installs).
- Backlog integration: all `backlog_*` tools, CLI helpers, `TaskInfo`, and the canonical Backlog.md instructions live in `@ezxomp/backlog`; cook consumes helpers/types via cross-package imports from `@ezxomp/backlog/extensions/index.ts` and must not redefine or re-register any of it. Cook does NOT re-register the `backlog_*` suite (backlog's own entry owns registration) and does NOT re-append the quality-standards block (backlog's unconditional default overlay is the single injection point) — co-install duplicates would shadow tools and double-inject guidance.
- Cook agents ship under `agents/` as a ten-profile roster (existing OMP roles plus upstream-derived `cook-audit` and `cook-refute`) and are installed to `.omp/agents/` (project) or `<omp-home>/agents/` (personal; `<omp-home>` = `$OMP_HOME` or `~/.omp` — mirrors evo's `paths.ts` resolution). `session_start` auto-syncs both scopes (`syncCookAgents` in `extensions/agents.ts`): a `.cook-agents-marker.json` records the plugin version + per-profile template hash; install re-runs only when the marker is missing, the version differs, or an installed profile drifted (evo-sub rewrites, manual edits). Auto-sync SKIPS both scopes when evo-sub owns the profiles — detected via real YAML parse of `<omp-home>/agent/config.yml` (`evo-mode.sub === true`, matching evo's `config.ts` boolean semantics) OR existence of evo-sub's `sub-state.json` (conservative: any state file counts as ownership). Writes are atomic (temp+rename) so concurrent OMP instances can't expose torn profiles. Explicit install stays available via `cook_install` and `/cook install`.
- Profile resync is additive for operator customization: every shipped frontmatter key and the complete body come from the current template, while installed frontmatter keys absent from that template (for example `model` or `provider`) survive. The marker hashes the merged installed bytes so a preserved pin converges instead of forcing a reinstall loop.
- **Spawn authority** across the roster: the orchestrator, `cook-planner`, and `cook-researcher` may call the native `task` tool; `cook-judge`, `cook-worker`, `cook-validator`, `cook-scout`, `cook-audit`, and `cook-refute` must not (their frontmatter omits `task`). Judge requests scout evidence in its verdict; the orchestrator dispatches.
- **Terminal/coordination contract**: every profile grants `hub` and `yield`, ends only by invoking `yield`, and uses explicit `hub({ op: ... })` calls. Role-specific methods must have matching frontmatter grants; notably workers can read their Backlog task and validators can append gate journal evidence.
- **Tool directives**: every profile carries a conditional `## Tool Directives (codesight)` block — when `codesight_*` tools are registered, agents prefer them for grounding (summary/wiki/symbol index/blast radius/import graph) and skip silently when absent. Keep the conditional phrasing: cook must work on OMP installs without the codesight plugin.
- **Parallel-work protocol pointers**: profiles and `dispatchPayload` reference the consuming project's `docs/parallel-agents.md` (single source of truth — one `git worktree` on branch `task/<slug>` per task, branch + immutable `HEAD` OID as the deliverable, workers never push or move `main`; coordinator integrates serially and is the sole `git push origin main` actor). Cook never copies the protocol text; if the protocol changes, only that doc changes. Workers that push or mutate `main` directly fail validation/judge gates; validators and judges use read-only Git inspection only.
- **Coordination root**: canonical realpath of the project cwd owns `backlog/cook-state.json`, the append-only journal, and the interprocess lock. Every tool/command transaction reloads persisted state under that lock before readiness, capacity, activation, and commit. State acceptance follows atomic same-directory write/fsync/rename; errors propagate without accepting in-memory ownership. Missing state initializes defaults; unreadable/malformed state or journal requires explicit operator recovery, never a reset. Preserve abandoned lock evidence; remove a stale lock only after proving its process no longer owns it.
- **Readiness**: `state.ts` owns the eligible `To Do`/`todo`/`In Progress`, unclaimed, terminal-dependency predicate and high/medium/low/unprioritized ordering. Turn reconciliation never activates a sibling; explicit `cook_next` uses the same locked claim path as `cook_claim`. Retain the completed pointer while open siblings remain so explicit iteration stays possible.
- **Dispatch contract** (`extensions/cook-tools.ts` `dispatchPayload`): `cook_dispatch_*` tools probe the session's ACTIVE tool surface (`getActiveTools()`, falling back to registered `getAllTools()` on legacy hosts) for OMP's native `task` tool before emitting the brief — registered-but-inactive does not count. Active → structured dispatch payload (`task({ agent: "cook-<role>", task: <brief> })`). Absent/inactive → `isError` remediation that forbids omp-CLI improvisation and inline simulation; unreadable/missing surface (legacy host) → payload without the probe. Never turn dispatch tools into prose-only instructions — the probe is the durability guarantee.
- **Lifecycle/result contract**: dispatch appends its write-ahead intent and `agentLog` fact before projection. After the fresh specialist returns, the orchestrator records the typed outcome through `cook_record_result`; `cook_advance` rejects a stage without a later durable result. Failed/blocked results require a typed finding and route to the finding's `kickTo` stage. Repair results supply the worker's actual `modified_files`; missing or out-of-scope file evidence forces a full judgment reset, while proven file-confined repairs may retain unaffected sibling findings. Every recovery writes a fresh intent so a prior-cycle result cannot advance the new cycle. Per-source convergence caps allow at most one strictly shrinking implement-only bonus; the next failure persists a council episode. The orchestrator must then run `cook_dispatch_council` (one parallel batch of integrity/security/pragmatist inquiries), pass exactly three votes to `cook_dispatch_council_synthesis`, and commit its `plan`/`implement`/`verify` route through `cook_record_council`.
- **Attempt lineage**: journal `cycle` intent (and legacy `Fresh ...` recovery intents) bounds current dispatches; retain old history without letting its failed/orphaned attempts veto repaired stages. Validator/judge `supersede` must name an unsettled current orphan, then starts a fresh attempt. Record every parallel result with exact `dispatch_stage`; settle the complete batch, union typed blockers, choose the earliest required recovery, and consume one cycle independent of arrival order. A validator gate uses `stage:"verify"` plus the emitted exact `dispatch_stage`; standalone gates cannot settle a dispatch, and stale/mismatched receipts are rejected.
- **DAGR/view contract**: `buildDagrProjectionInput` pairs intents and terminal facts by task, stage, and sequence; projection exposes honest task kind/project, attempt receipt, locator, and liveness. Every relevant mutation and active turn refreshes `.dagr/run.json` through strict validation. Projection remains best-effort and never gates the workflow.
- **Watcher isolation**: one watcher owner starts/stops immediately after tool/CLI commits and session restore. Native directory fan-out monitors existing/new nested task/doc paths on Linux, excludes symlink traversal and dot/state/config churn, and closes every timer/watcher on stop. Manual notifications use `triggerTurn:false`. Queued events may persist only their owning cwd timestamp and never repaint or trigger a different cwd; persistence failure cannot trigger a successful turn.

## Work Guidance

- **Conditional upstream stations**: `cook_dispatch_audit` uses `cook-audit` for independent security review; `cook_dispatch_refute` uses `cook-refute` for one source-bound blocker. Existing planner/worker/validator/judge profiles remain the OMP equivalents for plan/implement/verify/review.
- Roles: planner, scout, researcher, worker, validator, judge
- Activity surfaces: active state transitions update `ctx.ui.setTitle` and `ctx.ui.setWorkingMessage` only when `ctx.hasUI`; state-owned values are cleared on reset, cwd/session switch, session stop, and shutdown without overwriting host replacements.
