## 3. OMP Default System Prompt Architecture

### Structure

The current OMP default system prompt is 14.3 KB and organized into these sections:

1. **§ Role** — "Helpful, trusted assistant for load-bearing changes in Oh My Pi coding harness."
2. **§ Runtime** — Skills & Rules (reads `skill://` first), Internal URLs, Tool Policy
3. **§ Engineering** — Correctness first, compiled code efficiency, maintenance
4. **§ Personality** — Evidence-first terse engineer
5. **§ Tone** — Fragments, no ceremony, concrete, reasoning format
6. **§ Reasoning Format** — Problem/Decision/Check/Next
7. **§ Succinct Patterns** — Y → need update X
8. **§ Escalation** — Push back on risk-hidden plans
9. **§ Workflow** — 6-phase (Scope → Research → Decompose → Implement → Verify → Cleanup)
10. **§ Delivery** — Inviolable rules on completeness, evidence, clean cutover

### Strengths

- **Rigorous verification mandate** — requires running tests/commands before claiming completion
- **No-yielding rule** — agents must complete work before yielding
- **Evidence-first personality** — facts over fluff
- **Tool policy** — mandates lean-ctx tools over native equivalents
- **DOX framework** — AGENTS.md hierarchy as binding work contracts

### Weaknesses

- **Overly verbose** — 14.3 KB is high context cost; much content is boilerplate
- **No communication style overlay** — lacks the clear/concise/actionable discipline from reference repo
- **Redundant sections** — Personality, Tone, Reasoning Format overlap significantly
- **No aliases** — no shortcuts for common communication patterns (e.g., `scr`, `eli`, `foc`, `ref`)
- **No boundary reminders** — lacks explicit "do not widen scope" guardrails

## 4. How OMP Agents Function With ezxomp Plugins

### Plugin Architecture

ezxomp is a TypeScript monorepo of OMP plugins. Each plugin under `plugins/` extends the agent harness with domain-specific capabilities:

| Plugin | Package | Purpose |
|--------|---------|---------|
| augment | @ezxomp/augment | Augment-style prompt rewriter — one command, stronger prompts |
| better-custom | @ezxomp/better-custom | Typed custom-provider wizard boundary |
| code-nav | @ezxomp/code-nav | Exact symbol navigation companion between CodeSight discovery and native LSP operations |
| codesight | @ezxomp/codesight | Structured AI context map (`.codesight/CODESIGHT.md`) for token-efficient codebase onboarding |
| experiences | @ezxomp/experiences | Human-reviewed habits for coding agents — local-first behavioral learning layer alongside skills and memory |
| extensible-workflows | @ezxomp/extensible-workflows | Saved-recipe persistence and authoring layer for OMP native workflows |
| pix-skills | @ezxomp/pix-skills | Agent skill loader (`read_skills` tool + skills bundle) |
| plannotator | @ezxomp/plannotator | Interactive plan review with annotations, annotate agent messages, review code/PRs |
| pstack-suite | @ezxomp/omp-pstack-suite | Unified agent workflows: code quality, PR review, docs, CI, team ops |
| skills | @ezxomp/skills | Agent skill loader (`read_skills` tool + skills bundle) |
| skillforge | @ezxomp/skillforge | Improving agent skills through verified project memory |
| ultra-compact | @ezxomp/ultra-compact | Automatic threshold-based compaction with critical context preservation |

### Agent Capabilities (Injected Tools)

Plugins register extensions via OMP's extension API. The agent receives these tools:

- **Core navigation:** `ask`, `eval`, `hub`, `learn`, `recall`, `reflect`, `read`, `todo`
- **Codebase context:** `lean-ctx/*` family (83 MCP tools covering read, search, shell, glob, etc.)
- **Task orchestration:** `task` — dispatches subagents with `cook-${role}` naming
- **Peer coordination:** `hub` — message bus between agents
- **Workflow:** `backlog/*` — Backlog.md task management; `cook` — recipe-driven CI/CD
- **Plugin management:** `ezxomp-marketplace`, `omp-plugin-authoring`
- **Browser automation:** `camofox/*` — anti-detection browser control
- **Search & docs:** `hound/*`, `context7/*`, `web_search`

### Context Injection Pipeline

1. **AGENTS.md hierarchy** — injected as `<repo-rules>` block; DOX framework enforces read-before-edit chain
2. **Plugin manifests** — `omp` key in package.json registers extensions, tools, hooks
3. **Skill discovery** — skills in `.omp/agent/skills/` and `~/.omp/agent/skills/` discovered at session startup
4. **lean-ctx compression** — ctx_read/ctx_search/ctx_shell compress tool I/O by 60-131x
5. **Memory** — `learn`/`recall`/`reflect` for cross-session durable memory

### Multi-Agent Workflow

The `task` tool dispatches fresh-context subagents for parallel work:

- `cook-planner` — task decomposition
- `cook-scout` — codebase reconnaissance
- `cook-researcher` — research & analysis
- `cook-worker` — implementation
- `cook-judge` — code review

Agents communicate via `hub` (message bus) and `lean-ctx-ctx_agent` (shared message bus with stigmergic scent field).

## 6. System Prompt Upgrade Proposal

### Approach: Append-Style Overlay

Following the reference repository pattern (`--append-system-prompt`), the upgrade should overlay a communication discipline on top of the existing OMP system prompt rather than replacing it entirely.

### Upgraded Components

1. **Condensed personality** — merge § Personality, § Tone, § Reasoning Format into a single concise directive
2. **Communication style overlay** — import the "Clear, Concise, Actionable Communication" discipline from SR Opus 5
3. **Reference point codes** — adopt D1/D2/DN, O1, F1, R1, Q1, A1 coding for findings
4. **Aliases** — `scr`, `eli`, `foc`, `ref` shortcuts
5. **Hard boundaries** — explicit "do not widen scope" guardrails

## Scope Change Note

During implementation, deployment was elevated from project-local to global. Correction (2026-08-22, post-deployment review): harness ground truth renders a discovered `SYSTEM.md` as the agent's custom system prompt, REPLACING the default prompt body — in the harness's system-prompt assembly, discovery of `SYSTEM.md` fills the replacement slot while only `APPEND_SYSTEM.md` feeds the append slot. The exact source location shifts between harness releases, so this is cited by behavior, not line number. The overlay content was therefore folded into a single `~/.omp/agent/APPEND_SYSTEM.md` (SR Opus 5 overlay + OMP Agent v1 upgrade blocks) and `SYSTEM.md` was removed (backup: `~/.omp/agent/SYSTEM.md.disabled.bak`). Project-local copies remain removed; the global location is the single source of truth and the OMP core contract is never replaced.
